# 规则集质量与维护约束

本文件说明当前配方、构建和导出的质量边界。集合范围与数量以当前配方和构建清单为准；语法、已知场景与区间校验不能逐站证明所有权、实时可达性或代理可用性。来源用途与许可见 [SOURCES](SOURCES.md)，验证层次见 [VALIDATION](VALIDATION.md)。

## 组织原则

四类目录表达不同问题：

| 目录 | 回答的问题 | 允许的重叠与边界 |
|---|---|---|
| region | 目的地址的位置意见；CN 另提供国内域名场景 | 每个内部地区只公开一次。CN 域名优先、IP 兜底；其他地区不按总部或 ccTLD 推导厂商域名 |
| provider | 厂商生态、明确产品或托管平台的范围 | 总集和子产品可嵌套；云平台租户网络只说明承载平台，不能识别最终 App |
| category | 多种产品的共同用途 | 可与服务商重叠；逐用途选择成员，必要时仅投影域名，不继承整个综合集团 |
| special | LAN、推送、HTTPDNS、广告、遥测等谓词 | 可与其他目录重叠，不隐含直连、代理或拒绝；启发式关键词不等于身份保证 |

同一产品出现在多个用途分类中不自动算冲突。地区规则之间、地区规则与完整 Anycast 规则之间必须满足相应互斥约束；`ip-library.csv` 另保留 Anycast 标记及已有地理来源的确定性回退，便于明确表达两者的不同语义。服务匹配通常应优先于用途、厂商总集和地区 IP。最终文件保留 AirRoute 支持的有类型谓词，不强制拆成域名/IP 两套文件。

## 配方与输出约束

| 风险 | 当前约束 |
|---|---|
| 内部数据与公开产品混淆 | 保持唯一 `region/cn`；公开地区必须绑定内部地区且不重复绑定，不公开内部 `cn-geo` 下载集合 |
| 聚合列表与实际用途不同 | CN 不接受 `.ms`、`.top`、`in.th` 等宽泛顶级/注册边界根；使用 ICANN/PRIVATE PSL 检查及明确许可 |
| 关键词没有域名标签边界 | 普通服务的无边界关键词默认隔离，明确许可才保留；特殊用途集合保持其启发式语义 |
| CDN、鉴权、遥测等共享依赖 | 专用租户子域与公共根分开判断，不把公共遥测根或共享 API 根当作产品专属身份 |
| 托管平台与租户身份混用 | 供应商自有平台范围按 PSL 和官方端点说明显式批准；例外不自动传播给用途分类 |
| 综合集团与产品边界不同 | 购物仅投影零售范围，不继承 AWS 等基础设施；邮件不继承同集团 VPN；每项 include/exclude 在配方中明确 |
| 产品目录与官方端点变化 | 优先上游独立产品文件；手选端点保留来源、范围和复核日期，不把官方连通性清单整体当作产品身份 |
| 上游语法演进 | DLC include、属性与 affiliation 按实际语义展开；不支持或不完整的结构阻止构建 |
| IP 来源字段语义不同 | IPLocate/DB-IP 提供位置意见；运营商、BGP、登记与公共 geofeed 保留为辅助提示，不增加位置票或单独填补地理缺口 |
| GeoIP 含特殊用途地址 | 先按 IANA/RFC 策略裁剪；LAN 仅作显式例外，协议和转换范围不因全球可达就获得单一地理归属 |
| Anycast 粒度与部分部署 | 完整高置信度范围独立分类；partial、疑似和过宽候选不扩大 backing prefix，保留确定性地理回退及待补证状态 |
| 聚合丢失具体来源意见 | 按精确子范围保存位置意见和辅助提示；所选 RIS 视图不可见的范围仍保留，不伪造父路由 |
| 无关变化导致观测失效 | 辅助网络提示不充当位置证据，也不因提示边界变化重开等价位置任务；指纹保持与实际语义相关 |
| 镜像与重复聚合 | 对原料和有类型谓词去重；多个镜像一致不增加独立地理置信度 |
| 客户端能力与平台差异 | 仅保留可表示的原子谓词和语言等价正则转换；不支持的结构失败，不把 AND 改成 OR；元数据能力依赖实际客户端 |
| 来源删除、截断或不可用 | Git 来源固定 SHA，动态输入保留摘要，执行完整性、选择器与每集合条数门禁；失败不切换有效版本 |
| 优化改变匹配范围 | 域名删除项保留最终覆盖证明，IP 聚合保持精确区间等价、不填洞；压缩不创造宽根域或无边界关键词 |
| 公开产物混入内部数据 | 最终仅交付规则、生成 README 和 `ip-library.csv`；缓存、原始观测、任务与凭据不进入公开目录 |

`.ms` 是 Montserrat 的 ccTLD，`.top` 是通用顶级域，不能作为中国大陆身份，见 [IANA ms](https://www.iana.org/domains/root/db/ms.html)、[IANA top](https://www.iana.org/domains/root/db/top.html)。公共统计端点的含义见 [Cloudflare 官方说明](https://developers.cloudflare.com/web-analytics/data-metrics/data-origin-and-collection/)。

PSL PRIVATE 边界表达租户隔离，不代表平台不属于服务商，也不能把平台范围推广成租户的具体产品身份。参考 [PSL 主表](https://publicsuffix.org/list/public_suffix_list.dat)、[Akamai 域名说明](https://techdocs.akamai.com/edge-hostnames/docs/edge-hn-terminology) 与 [GitHub 用户内容域名说明](https://developer.github.com/changes/24/)。

其他语义依据包括 [china-operator-ip](https://github.com/gaoyifan/china-operator-ip)、[DLC 语法](https://github.com/v2fly/domain-list-community/blob/master/README.md)、IANA [IPv4](https://www.iana.org/assignments/iana-ipv4-special-registry/) / [IPv6](https://www.iana.org/assignments/iana-ipv6-special-registry/) 特殊地址表与 [Anycast Census](https://github.com/ut-dacs/anycast-census)。

## 日常构建与补证

1. 解析 Git 来源后固定 SHA，下载本次依赖；动态输入保留摘要。离线重放使用已接受的完整快照，不以半份来源静默替代。
2. 展开有类型规则、DLC include/属性/affiliation，按配方成员或显式投影组织集合。
3. 域名按 IDNA、标签边界、PSL、共享依赖、排除子域和显式互斥关系清洗。先清洗再去重，避免过宽父后缀吞掉有效子域。
4. IP 按完整区间对齐地理来源、Anycast、BGP 与提示，先应用特殊地址策略。优先适用的合格事实，再按独立位置来源严格多数和固定主备选择；有效分歧不直接导致范围缺失。
5. 对仍缺材料的事项保留精确来源意见和语义指纹。纯位置分歧不能用 traceroute 回答，不生成无效主动任务；可补充端点材料的问题按 BGP 内同质连续范围安排有限候选。已有目标优先，IPv4 可作稳定有限补充，IPv6 仅使用已知精确候选，不扫描子网。
6. 全部集合和 `ip-library.csv` 通过质量校验后才激活完整版本，再进入发布队列；失败保留有效版本。发布不等待全部待补证事项完成。

当前观测入口没有可信目标位置或服务所有权事实导入源。DNS、目标响应、负响应和路径只提供各自范围内的材料；候选选择标记没有观察时间，不能冒充已响应证据。共享尝试次数和未知提交防重边界见 [SCHEDULING](SCHEDULING.md)。

`quality.json` 的条数门限用于发现异常，不能证明数据正确。预期范围变化须同步修改配方、门限和正反场景，不能为通过构建盲目降低门限；人工 include 也必须通过顶级域、关键词与 IP 安全门禁。

## 持续限制

- 位置来源一致不等于位置真值。数据可能共享原料或同时滞后；BGP、注册国和 RTT 不能单独证明物理国家。全部有效地理意见和事实缺失时明确记录覆盖缺口。
- 域名不能总是分开产品边界。同主机的不同 URL、共享产品端点与云/CDN 地址限制了应用鉴别；手选子集不承诺完整产品连通性。
- 覆盖与误匹配需要按样例权衡。隔离未确认的共享根或关键词可能减少边缘功能覆盖，应结合上游变化及已确认的漏匹配/误匹配维护配方。
- DNS 污染、DoH/ECH、代理出口和客户端元数据影响实际命中。DNS 观测不永久写成产品归属，缺少域名或使用共享 IP 时不能恢复精确 App 身份。
- Anycast 清单不完整。低分、partial 或过宽 backing 范围不能直接证明单地或多地，精确目标响应也不能裁决整个前缀的 Anycast 属性。
- 增量复用不能发现所有静默迁移。未变来源继续复用，需要明确失效条件、新独立证据或反馈重开；不以固定周期全量重探代替语义判断。
- 官方端点事实需持续复核。引用与日期不表示自动同步官方全文；新增共享端点仍须判断用途，必要许可证与署名随分发保留。
- 本地测试、协议连通和构建成功分别证明各自边界，不能代替公网覆盖、第三方提交、远端发布或各平台 VPN 的端到端验收。
