# 域名来源与转换记录

本页解释已选公开材料及生成边界，不建立逐条身份审批系统。实际来源、版本、获取时间、摘要和解析数量在每轮记录中；过去固定版本的条数不能冒充本轮结果。

| 来源 | 选择与用途 | 血缘边界 |
| --- | --- | --- |
| DLC 原始 data | include、属性、affiliation、具名产品/类别；中国分流输入和俄罗斯服务类别 | 一个生成链，不将 include 数当作独立证据 |
| blackmatrix7 China/ChinaMax | 主体与 `_Domain` 伴随文件共同展开；中国非 IP 产品的重要输入 | ChinaMax 含多个社区共同上游，格式、镜像和子集不加票 |
| blackmatrix7 具名服务文件 | 按配置贡献对应 provider/category，不要求厂商根域或独占证明 | 共享云/CDN 是连接范围，不据此宣称所有客户身份 |
| ACL4SSR | 中国分流、媒体、具名服务与特殊用途的已选文件 | 与其他社区可能共享原料，来源不同不等于独立 |
| Sukka | 已选 domestic、domestic_cdn、AI、stream 等具名用途 | domestic_cdn 是生成子集；不把每个格式算独立来源 |
| 官方机器目录 | Microsoft 365、GitHub、Telegram 等实际端点及服务 IP | 单个依赖端点不扩张成整家平台或 ASN；官方服务范围不是物理地区 |
| 固定旧客户端语料 | 语义迁移对照 | 未有逐条血缘时写明来源未知，不虚构归因 |

China/ChinaMax 的 DOMAIN-SET 引用必须正确读取伴随材料，不能只读取主体而丢成员。解析器保留合法单段 TLD、关键词和可表达正则，不因域名外观、没有点、不属于自定义 owned_roots，或另一名单没有收录而拒绝。`PROCESS-NAME`、`IP-ASN` 等 Core 支持的非 CIDR 类型也保留；中国非 IP 产物不混入上游 CIDR；该限制是产物类型约定，不是将所有服务来源 IP 一律丢弃。

Microsoft 365 中国目录不要求域名以 `.cn` 结尾。共享端点、第三方连接依赖及服务 IP 保留其实际范围和来源，不统一以“不能证明独占”隔离。配置中的排除只能在确能证明规则被排除范围覆盖时执行；正则是否相交未知不能当作确定相交。

俄罗斯 DLC `category-ru` 与具名银行、机构、运营商、服务仍用于 `category/ru-services` 及相应 provider/category。它们不再作为地域域名输出。其他已选地域服务域名同样按用途移动，不将欧洲、港澳、东北亚等域名留在 IP 地域列表中。

原始条目、展开后条目、可表达条目、合并去重及最终输出分别计数。一个精确域名被父后缀覆盖时记录覆盖关系，不能说成丢失。不能表达的 AND/NOT、UA、MITM、未知方言等保存来源、类型、数量和原因；不把复合条件拆成更宽的正向匹配。

CN 与其他用途集合允许重叠，不再通过 `-cn`、`!cn`、具名大陆差集或笼统冲突门槛删掉全球类别中的中国成员。上游分类是生成基础，不保证绝对正确；只做明确且必要的格式/语义处理，来源与组合由配置展示。完整记录及查询见 [BUILD_RECORDS](BUILD_RECORDS.md)。
