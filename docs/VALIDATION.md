# 检查、构建与交付证据

当前改造按基本检查、相关小型夹具与一次完整 Actions 构建交付，不另建大规模验证平台或独立审计流程。本文列出检查职责；具体通过数量、运行 ID 和发布提交以本次实际记录为准，不继承旧实现的成功结论。

## 保留的工程检查

- 来源和候选路径不得越界、带链接或隐式覆盖；归档下载/展开有体积和成员边界。
- 固定输入逐文件长度、摘要、版本和格式校验；主地域源整库下载或解析失败明确失败。
- 精确、后缀、关键词、正则及 CIDR 的语义转换不能扩大匹配；不支持类型留可追溯原因。
- 最终客户端目录只有 region/category/provider/special；CN 拆成 IP 与非 IP，其他地域只含 IP；没有 Geo 或隐藏 Geo，只有 special/asn.ardb。
- manifest 与实际文件、列表族、目录、长度及 SHA-256 一致；ASN 二进制检查头、目录、偏移、保留字段、整数边界、地址规范化与双栈结构。
- ASN 输入存在有效 IPv6 时，生成不能丢光 IPv6。来源本就没有某族、真实空数据和解析失败分别报告，不能混淆。
- LAN 不误收 FakeIP 池，统一 RealIP 只有可表达的域名匹配数据，不混入动作、CIDR 或解析器。
- 发布为一个完整 Git 提交，保留并发与源码身份防护；失败不覆盖上一有效版本，普通非 force push，超时按已有提交身份恢复。

不再以历史保留比例、增长比例、最少条目数/地址数/指定域名数判定内容“正确”；比较保留为报告。可选报告或可选输入缺失不无条件阻断核心产物，但其已生成文件损坏、manifest 不一致仍是工程错误。

## 基本本地命令

```sh
python3.12 -m compileall -q airroute_data
python3.12 -m unittest discover -s tests -v
# 快照与完整生成命令见 README；输入和输出每轮使用新目录
python3.12 -m airroute_data validate .build/candidate
```

小型夹具检查重点为：固定优先源及按段补缺、同源更具体范围、IPv6 宽段和仅 IPv6 备选、冲突保留主源、来源失败、CN/全球类别重叠、include/属性、合法 TLD、共享端点和正则不明相交不误删、ASN 多源多起源及双栈、RealIP 合并、旧目录不复生。它们不是全网地理准确率实测。

## ASN 文件互操作

格式为既定 ARDBv001，说明与黄金样例见 [FORMAT](FORMAT.md)。Python 写入和读取可以在本仓库验证；实际客户端/Core 的读取验证需要对其真实源码及同一文件进行测试。缺少外部源码时必须标记跳过，不能把离线 Python 格式测试称为客户端集成成功。没有 Geo 输出，也不为旧客户端保留 Geo 兼容文件。

## domains-only

仅接受通过工程校验的当前格式基线。地域 IP 列表、ASN 及其真实来源版本/时间原样复用，记录基线身份和内容摘要。完整构建才可更新地域策略/注册表；旧 Geo 库不能成为隐藏的中间依赖。该命令成功不意味着本轮重新取得了地域数据。

## 失败记录

来源获取、解析、转换、候选生成、工程校验和发布各有状态。下载失败不能伪装成空来源成功，失败 artifact 尽力保留已产生的来源、统计、比较、冲突和索引；诊断整理或上传失败不得覆盖原始错误。生成成功、artifact 上传与真实发布是不同结论。

旧的运行计数和二进制对比只说明旧提交；例如旧五源运行 41778397925 的失败诊断成功留存，不证明本次改造通过。新版本的完成情况应链接本次 Actions、记录和远端提交，未执行的部分如实标记。详细查询见 [BUILD_RECORDS](BUILD_RECORDS.md)，发布与迁移见 [PUBLISHING](PUBLISHING.md)。
