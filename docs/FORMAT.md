# AirRoute ASN 二进制契约 v1

本项目只生成一个客户端数据库：`special/asn.ardb`。它是规则编译时按需展开 ASN 的只读输入，不要求客户端在运行时常驻整库；不输出或复用 Geo 数据库。地域直接使用 `region/*.list`。文件不是 `.list`、`.ari`、MMDB 或本机内存镜像，不整体压缩。

保留已约定的 `ARDBv001` v1 字节契约。整数均无符号小端，IP 地址按网络字节序；偏移从文件起始计算，单位为字节。

## 文件头与目录

64 字节头：

| 偏移 | 类型/长度 | 值 |
| --- | --- | --- |
| 0 | ASCII 8 字节 | `ARDBv001` |
| 8 | u16 | 格式版本 `1` |
| 10 | u8 | ASN 类型 `2` |
| 11 | u8 | 保留零 |
| 12 | u32 | 组数 N |
| 16 | u64 | 目录偏移 `64` |
| 24 | u64 | 数据区偏移 `64 + 28 × N` |
| 32 | 32 字节 | 全零保留区 |

每个目录项 28 字节，按正整数 ASN 数值严格升序且唯一：

| 相对偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0 | u32 | ASN 组 ID |
| 4 | u64 | IPv4 数据偏移 |
| 12 | u32 | IPv4 CIDR 数量 |
| 16 | u64 | IPv6 数据偏移 |
| 24 | u32 | IPv6 CIDR 数量 |

空地址族的偏移与数量同时为零。允许空组；缺失组和空组都不表示匹配全部地址。不同 ASN 组可包含同一网段，多起源数据不会因目录唯一性而丢失。

## CIDR 记录与生产者布局

- IPv4：4 字节规范化网络地址 + 1 字节前缀长度，共 5 字节。
- IPv6：16 字节规范化网络地址 + 1 字节前缀长度，共 17 字节。
- 前缀长度分别不超过 32 / 128，主机位必须全零。
- 同组先 IPv4 后 IPv6，各族按 `(网络地址, 前缀长度)` 排序，确定性无损去重和合并。
- 本生产者使用连续、紧凑、组间不共享物理负载的布局，不写间隙或尾随数据。v1 线格式允许合法的负载共享；生产者采用更严格的规范输出策略，不改变线格式。

写入使用临时文件、同步和原子替换。manifest 将 ASN 格式版本、数据版本、长度和 SHA-256 与同轮所有 `.list` 绑定；客户端安装时应核对实际文件，不能只信文件名。未知组、错误类型、损坏或不支持的版本应明确失败。

`read_database()` 验证头、完整目录、保留字段、目录顺序、正 u32 ID、偏移边界及 u64 溢出、截断、空族偏移、网络地址与前缀、排序和无损合并。每目录最多 1,048,576 组，每组最多 1,048,576 前缀，与 Core 的读取边界一致。这是结构边界，不是内容数量或历史变化的发布门槛。生产校验还会核对实际 ASN 输出的地址族是否保留本轮合格输入已有的 IPv4 / IPv6，不能只检查文件可打开。

## ASN 数据含义与比较边界

字节格式不变，但正式数据库只采用 **MaxMind GeoLite ASN**（`maxmind-asn`）的双栈 IP-to-ASN 数据，不再将 BGP/IPtoASN 多源观测并入正式文件。ASN 数值和范围来自该上游，不维护厂商归属白名单；同源先按更具体范围选择，再作 ASN/地址资格过滤和无损规范化；未知或特殊 ASN 子段仍遮蔽父段，不能因过滤而从宽父段重新补满。不据组织名称扩张地址。源的组织描述不证明物理地理位置、独占所有权或实际使用。

正式输入有有效 IPv4/IPv6 时，相应族必须保留到输出；来源解析失败不能被误读为该族真实无数据。正式来源缺失、文件损坏、空族或解析失败不能用 BGP/IPtoASN 顶替。不同 ASN 在 v1 中仍允许跨组重叠，这项线格式能力不等于声明 MaxMind 输入涵盖全部 BGP 多起源。

地址资格由本轮固定 IANA allocation 与 special-purpose 文件提供，Geo/ASN 分开处理：ASN 先取已分配/legacy，再按更具体 Globally Reachable TRUE/FALSE/N/A 属性处理。TRUE 特例可保留，FALSE/未确定项不作为客户端展开；不得把 Geo 的全部特殊用途排除直接复用为 ASN 规则。资格只限定可生成范围，不证明实际路由或地域。

特殊号码依据 [IANA Special-Purpose AS Numbers](https://www.iana.org/assignments/iana-as-numbers-special-registry/) 与 [IANA AS Numbers](https://www.iana.org/assignments/as-numbers/) 区分 AS0、AS_TRANS、文档、私用和保留号码。原始资料和原因保留，不把特殊号观测说成上游错误；AS112 是全球可路由的特殊用途，不按私用号删除。

RIPE RIS、Route Views、IPtoASN 等保留为独立比较：原始来源、collector/peer、聚合记录、多起源、更具体和宽前缀均可追溯。不同实际 peer 不能混成一个 peer 后互相覆盖，RIS 缺少逐 peer 身份时如实标记。宽前缀不以 `/8`、`/12` 一刀切隐藏；`/0` 作为默认转发语义单列，不解释为整个地址族的实际使用。它们与正式文件的不同不自动证明哪一方错误，也不偷偷修改正式 ASN。

## 黄金样例与互操作边界

`tests/golden/asn-v1.ardb` 固定双栈、跨组重复 IPv4、仅 IPv6 的 32 位 ASN 等字节样例。结构损坏样例覆盖 magic、版本、类型、保留区、偏移、数量、排序、前缀与截断；生产者非规范布局样例独立验证负载共享和尾随字节的策略差异。所有地址都是文档网段，号码也可使用文档/私用 ASN，它们是线格式夹具，不是生产成员数据。

历史 `geo-v1.ardb`、注册表样例及 codec 中的 kind=1 仅保留为既有 v1 线格式测试夹具，不参与生产构建、历史地域复用、产物验证或发布，不要求客户端订阅或读取它们。不存在为通过旧校验而生成的隐藏 Geo 数据库。

基本检查：

```sh
python3.12 -m unittest discover -s tests -p 'test_ardb.py' -v
python3.12 -m unittest discover -s tests -p 'test_routing.py' -v
```

可选跨仓库互操作：

```sh
AIRROUTE_CORE_IP_DATA="$CORE_REPO/crates/ip-data/src/lib.rs" \
  python3.12 -m unittest discover -s tests -p 'test_ardb.py' -v
```

测试在临时目录编译实际 Core 读取器，再使用 `tools/verify_ardb.rs` 读取同一组黄金字节，不复制另一套 Rust 解析器，不修改客户端。没有真实 Core 源码或 `rustc` 时明确跳过。此处提供验证入口，不把以前的互操作结果外推为本轮客户端订阅安装已就绪；此次未修改客户端或 Core。
