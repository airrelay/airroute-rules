# AirRoute Geo / ASN 二进制契约 v1

Geo 与 ASN 各为一个不整体压缩的只读 ARDB 文件。它们是 AirRoute 规则编译输入，**不是** `.list`、`.ari`、MMDB 或本机内存镜像。整数均无符号小端；地址字节均为网络字节序。偏移相对文件起点，单位为字节。

## 固定文件头：64 字节

| 偏移 | 类型/长度 | 值 |
| --- | --- | --- |
| 0 | ASCII 8 字节 | `ARDBv001` |
| 8 | u16 | 格式版本 `1` |
| 10 | u8 | `1` = Geo；`2` = ASN |
| 11 | u8 | 保留，必须为零 |
| 12 | u32 | 组数 N |
| 16 | u64 | 目录偏移，必须为 `64` |
| 24 | u64 | 数据区偏移，必须为 `64 + 28 × N` |
| 32 | 32 字节 | 保留，必须全零 |

## 目录项：每组 28 字节

| 相对目录项偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0 | u32 | 组 ID |
| 4 | u64 | IPv4 数据偏移 |
| 12 | u32 | IPv4 CIDR 数量 |
| 16 | u64 | IPv6 数据偏移 |
| 24 | u32 | IPv6 CIDR 数量 |

目录按正整数 ID 严格升序且唯一。ASN ID 就是 ASN 数值，允许 ASN 的不同组包含同一网段（MOAS）。Geo ID 使用 [`config/regions.json`](../config/regions.json) 的版本化大区注册表；当前版本 `airroute-regions-v1`。不把 ISO 国家代码或其整数编码隐式当作 Geo ID。俄罗斯为独立 `ru` 组，不同时并入欧洲/亚洲。ID 一旦发布不可改义或复用；注册表变更与客户端安装边界一起管理。

空地址族的偏移和数量**同时为零**，不指向数据区起点。允许完全空组和零组文件；缺失组、空组和未知 ID 是不同状态，不能将任一状态解释为匹配全部地址。

## 数据记录

- IPv4：规范化网络地址 4 字节 + 前缀长度 1 字节，共 5 字节。
- IPv6：规范化网络地址 16 字节 + 前缀长度 1 字节，共 17 字节。
- IPv4 前缀长度不超过 32，IPv6 不超过 128；主机位全零。
- 同组内先 IPv4 后 IPv6，各族按 `(网络地址, 前缀长度)` 确定性排序，无损合并、去重。
- v1 线格式允许不同组包含同一前缀，也允许它们的目录指向同一合法负载范围；每个范围必须独立满足边界和记录校验。ASN 的 MOAS 重复是合法业务数据，Geo 大区重复则由业务校验拒绝。
- 本仓库生产者选择每组写入独立数据块，不共享物理负载。这只是规范输出策略，**不是 v1 线格式禁止共享**。
- Python 生产者采用紧凑连续布局，不写未引用间隙或尾随数据。

`airroute_data.ardb.write_database()` 一组一组按目录顺序写入并增量计算文件摘要；不拼接整库内容后再哈希。临时文件完整写入并同步后原子替换候选文件。发布目录本身仍由发布流程管理，不直接覆盖客户端当前已安装的文件。

## 校验边界

`read_database()` 验证头、类型、版本、保留字段、目录长度与顺序、正 u32 ID、u64 偏移加法、所有负载范围、截断、空族偏移、地址族/前缀及网络规范化，并检查排序和可无损合并项。每目录最多 1,048,576 组，每组最多 1,048,576 前缀，与当前 Core 的读取上限一致。

Geo 调用必须在发布入口传入注册表 ID 集合 `allowed_geo_ids`；文件结构本身不能说明数字 ID 的业务含义。manifest 同时绑定格式版本、数据版本、Geo 注册表版本、文件字节数及 SHA-256，绑定两库与全部 `.list`。客户端安装时必须验证这些字段及真实文件摘要后才激活版本。未知组、错误注册表版本或不支持格式应明确失败，不猜测国家代码，不自动降级到另一组。

Core 的 `airroute-ip-data` 结构读取器在打开时验证头和完整目录，在读取指定组时验证地址/前缀；它刻意不实现发布安装、哈希或 Geo 注册表策略。Python 的生产产物验证器额外要求连续布局、不共享物理负载、无尾随字节和无损合并。线格式允许的共享负载或未引用尾部，不因此成为损坏的 ARDB；它们只是本生产者不生成、不接纳的非规范布局。该区别不改变 v1 契约。

## 同一组黄金样例

[`tests/golden/manifest.json`](../tests/golden/manifest.json) 固定记录样例的语义、长度、SHA-256，以及结构损坏、注册表不匹配或生产者非规范布局的不同分类；不在测试中从错误的 writer 自动覆盖黄金样例。

- `geo-v1.ardb`：双栈组 `1`、仅 IPv4 组 `9`、空组 `16`。
- `asn-v1.ardb`：双栈 ASN `64500`、共享 IPv4 网段的 ASN `64501`、仅 IPv6 的 32 位 ASN `4200000000`。
- 18 份结构损坏/不支持样例（`corrupt`）覆盖 magic、版本、类型、两个保留区、数量、目录/数据偏移、重复 ID、空族偏移、偏移溢出、IPv4/IPv6 主机位与前缀及三类截断。
- 1 份注册表不匹配样例（`registry_mismatches`）：`registry-unknown-geo.ardb`。
- 2 份线格式有效但不符合本生产者规范布局的样例（`producer_noncanonical`）：共享物理负载和尾随字节。Python 生产产物校验拒绝，当前 Core 结构读取器应允许；独立测试分别验证这两个结论，不能以“共同拒绝损坏输入”掩盖差异。

所有地址均为 RFC 5737 / RFC 3849 文档网段，**不表达真实 CN/RU 归属，也不能发布为生产地理数据**。

Python 离线校验：

```sh
python3 -m unittest discover -s tests -p 'test_ardb.py' -v
```

使用实际 Core 读取器验证 Python 黄金文件（不会修改 Core 仓库）：

```sh
AIRROUTE_CORE_IP_DATA="$CORE_REPO/crates/ip-data/src/lib.rs" \
  python3 -m unittest discover -s tests -p 'test_ardb.py' -v
```

此项测试把指定的真实 `airroute-ip-data` 源码编译至临时目录，再把 [`tools/verify_ardb.rs`](../tools/verify_ardb.rs) 链接到该库。工具本身没有复制或猜测二进制解析代码。缺少实际 Core 源码或 `rustc` 时，跨仓库测试明确显示 `skipped`，不能当作互操作通过。组数很多时验证工具的第三个参数可写为 `@组ID文件`（逗号分隔），避免命令行长度上限。普通生产构建不需要 Rust 环境，仓库没有 Rust 运行服务或 Cargo 项目。

当前已用实际 Core 读取器完成 **Python 写入 → Rust 读取**验证，包含双方共同拒绝的结构损坏样例。未知 Geo ID 样例是注册表不匹配，不是结构错误：底层 Core 读取器本身允许该正整数，黄金测试由安装边界包装器依据调用方注册表明确拒绝它；该区别有独立测试，不宣称底层解析器内置了业务注册表。生产客户端的下载、manifest 校验、`airroute-regions-v1` 安装、版本切换和应用 UI 配置仍属于客户端仓库范围；此次未修改或验证那些行为，不能由文件格式互操作推导它们已就绪。

一次跨仓库验证期间，外部 Core 的共享负载策略发生变化，原测试错误地把生产者策略当作 v1 线格式而失败。首个失败保留在本地 `.build/core-reader-contract-drift.log`；修复仅校正样例分类与测试 oracle，未改黄金字节、Core 或生产者输出。互操作报告必须绑定当次捕获的 Core 源码摘要，不将先前通过外推为任意未来版本通过。
