# 覆盖与变化报告的口径

本文件说明当前生成系统如何报告覆盖，不是固定条目配额，也不把历史发布大小当作内容正确性标准。最终数量、来源可用性与发布状态必须读取对应构建记录，不能从本页历史示例推断。

## 当前产品边界

客户端产物只有 `region`、`category`、`provider`、`special`。CN 为 `region/cn-ip` 和 `region/cn-domain`；其他 15 个地域只有 IP。俄罗斯域名是 `category/ru-services` 等服务用途，不进入地域列表。独立服务移至 `provider`，RealIP 合并到 `special/realip`；只有 `special/asn.ardb`，没有 Geo 数据库。

CN 与其他类别/服务规则可以重叠。类别包含独立服务时不能顺手丢成员；同一规则出现在两个用途集合不等于两个独立来源。来源组合由配置直接解释，文件行数不是网站数。

## 每次构建应查看什么

| 记录 | 应读信息 | 不能据此声称 |
| --- | --- | --- |
| 来源快照和解析统计 | 下载/缺凭据/失败/禁用状态，版本与摘要，IPv4/IPv6 读取与解析条数 | 配置五家就是实际五家、来源彼此独立 |
| 域名处理 | 原始与 include 展开条目、接受/不兼容类型、无损覆盖、最终谓词 | 文本未匹配就是实际网站缺口 |
| 地域融合 | 主源和备选实际选择范围、每源贡献、冲突与全部缺失，双栈前缀及地址量 | 冲突代表主源错误、地址量是活跃用户/主机数 |
| BGP/ASN | 原始采集视角、宽前缀、多起源、特殊 ASN、最终组内范围 | 通告是物理位置或整个范围实际所有权 |
| 版本比较 | 新增、消失、改变归类、未知及语义覆盖关系 | 文件变小必然覆盖变差、增长必然正确 |
| 发布状态 | 候选、工程校验、跳过/失败、核实后的远端提交 | artifact 上传就是正式发布 |

地域按真实区间切分后使用固定主源补缺顺序；冲突记录不删除有效主源输出。所有来源都无有效结果时保留未知，不把未知标成海外。域名使用成熟上游的产品/市场分类，不把位置结论作为其前置条件。

IPv6 既报告前缀数，也使用精确整数报告地址量；大的未观察宣告范围单列，避免稀疏宽段掩盖实际宣告前缀。BGP 仅作旁证，“未见”不等于不存在路由，两个计数不能相互冒充。

## 比较是诊断，不是内容裁判

不因历史增长/下降、某个集合未达到固定行数、固定地址量或指定域名数量而阻止发布。关键来源和选择器的真实错误、缺失情况及异常变化要如实报告；是否属于必需输入由明确配置和工程契约决定，不能用模糊“质量分”代替。

仍保留输入完整性、归档路径安全、格式合法性、manifest/产物一致性、ASN 双栈不丢失、原子发布和并发控制。损坏或无法表达的内容不因取消历史配额而变成有效数据。详情见 [VALIDATION](VALIDATION.md)。

## 历史证据的边界

此前 [Actions 41778397925](https://github.com/airrelay/airroute-rules/actions/runs/41778397925) 在旧的“跨源分歧即 unknown”策略下，五家均完成双栈解析，共 9,382,314 条输入；旧 IPv6 地址保留门槛导致构建失败，未发布。其诊断包曾完整保存源范围、冲突、比较和反查索引。该轮不是本次主源策略、四类目录、CN 拆分或 ASN-only 输出的验收，不能复用其数量与耗时宣称新版本通过。

本次修改的实际测试、构建及发布证据应随新运行保存；尚未执行的阶段不得填写成功。按域名/IP/ASN 查询与 artifact 保留方法见 [BUILD_RECORDS](BUILD_RECORDS.md)，旧路径迁移见 [PUBLISHING](PUBLISHING.md)。
