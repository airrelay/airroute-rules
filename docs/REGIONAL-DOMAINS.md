# 中国非 IP 规则与俄罗斯服务分类

域名市场/分流用途与 IP 地理数据是两条链。本版把这一区别落实为产物约定：只有中国大陆有地域名下的非 IP 产物；其他地域，包括俄罗斯，只输出 IP。

## 中国大陆

- `region/cn-ip.list`：地理主源及备选按区间融合后的 IPv4/IPv6。
- `region/cn-domain.list`：China/ChinaMax、DLC、ACL4SSR、Sukka 和官方目录等选定上游的域名及其他受支持非 IP 谓词。

`region/cn.list` 已移除，不保留长期兼容副本，也不在原路径下偷换语义。客户端应按用途订阅一个或两个新文件；这不指定 DIRECT/PROXY、解析器或最终兜底。

China/ChinaMax 的主体、Domain 伴随文件和引用需展开后合并。上游明确分类可以直接贡献，新增成员不要求先在身份目录或厂商根域中出现。仅做格式有效性、类型兼容、必要规范化和可证明等价的去重；不能把精确域名扩大为后缀，不能扁平化 AND/NOT。

合法单段域名不因没有点被丢弃；关键词和正则不再经过 bounded_service 等隐性门槛。来源有共享云端点，不等于可以把其整个云平台说成独占服务，也不成为统一删除端点的理由。Microsoft 365 中国目录按官方范围处理，不要求 `.cn` 尾缀。

中国服务也保留在全球 AI、开发、游戏、媒体、金融等适当类别和服务集合中。CN 与类别/provider 的同项是用途重叠，不是分类错误，不自动做差集或要求互斥。取消的只是“中国 AI”式无必要细分类，不是中国成员本身。

## 俄罗斯及其他地域

`region/ru.list` 只有 IP。DLC `category-ru` 和具名俄罗斯服务保留在 `category/ru-services` 及相应 provider/category，不把 `.ru` 后缀、公司注册地或 ASN 注册国转换成物理地域真值。

港澳、东北亚、欧洲、西亚等原有地域域名也不能留在地域列表；有价值的具名成员按银行、教育、媒体等实际用途迁移，不能为了地域改成 IP-only 顺手丢掉其服务覆盖。配置中的 includes 保持可追踪，不借迁移扩张单个服务为整家公司。

## 可追溯与比较

旧 CN/RU 固定语料用于语义覆盖比较。旧 CN 中的域名与 IP 分开比；旧 RU 若只有 CIDR，不能虚称完成俄罗斯旧域名迁移。历史条数不是恢复目标，不为满足数量盲目放宽匹配。

记录保存来源版本、选择器、展开、不可表达、压缩覆盖、最终集合和具体排除原因。集合相交只作解释，不依赖未声明的优先级，也不伪造 NOT。不能证明正则和排除根域相交时保留规则，而非当成已证明冲突删除。详见 [RULES](RULES.md)、[DOMAIN-SOURCE-AUDIT](DOMAIN-SOURCE-AUDIT.md) 和 [BUILD_RECORDS](BUILD_RECORDS.md)。
