# 按缺失证据共享调度

每日构建固定来源和已有观测，生成规则、IP 库及本轮仍需补证清单。新结果只供下一次构建使用，不逐条触发重建，不提供人工裁决入口。数据选择顺序见 [ARCHITECTURE.md](ARCHITECTURE.md)，运行证据见 [VALIDATION.md](VALIDATION.md)。

## 一份需求、一组执行身份

一个逻辑 job 表达精确目标、方法及必要观察视角；同一份缺失证据不按节点、账户或 build 复制。明确需要两个地区或独立 ASN 时才拆分。候选归属地区不是观察地区，默认没有第二视角、第二时间窗或机械的全地区门槛。

争议清单独立于具体任务：只对本轮策略选出的精确 IP 创建共享任务。控制台“缺少探测 IP”表示尚无符合策略的地址，不等于缺少执行节点或 Globalping 额度。人工临时探测和已知目标登记保留，但不是人工选择归属。需求级列表与读取投影继续表达实际需要，重试和节点数量不制造列表行。

### BGP 边界内的同质范围与有限 IPv4 候选

该策略只用于需要端点可达性补充材料的 `endpoint-reachability` 问题，不把全部地理来源分歧转换成待测任务。以本轮固定 BGP 视图和实际来源边界组织需求：同一个最长匹配前缀、起源集合、IPLocate/DB-IP 各自大区意见和疑似/部分 Anycast 状态相同，且地址连续的部分，才组成一组。geofeed 与运营商提示仍保留为线索，不因提示变化另拆抽样单元；不跨地址洞，也不跨本轮可见的更具体路由边界合并。问题列表展示实际子范围，详情中的 `bgp_prefix` 只是分组上下文，完整 `ranges` 才是该问题适用的地址范围；候选归属地区仍不是必须执行的观察地区。

`bgp-bounded-v1` 每组最多三个固定精确目标，优先使用范围内已有的 DNS 候选和端点响应依据。缺额时，仅在本组精确 IPv4 范围内按稳定 seed 补充候选；相同范围和选择输入得到相同地址，不因超时不断追加第四个样本或轮换全网段。`sample_plan` 保留策略、父问题标识、seed 与最多三个目标的计划，供原范围及历史工作关联。IPv6 不随机补地址，仍只使用已有精确候选；没有目标就继续等待，不枚举子网。

候选来源必须分开：`dns-answer` 是 DNS 候选，不保证目标响应；`endpoint-response` 保留原有响应观察时间与有效期；`sampled-candidate` 表示“范围抽样选取的 IP”，只记录选择来源，不表示该 IP 当前是否已经响应。选择依据不含响应观察时间或 TTL；后续真实响应及其时钟独立保存在执行记录中。该标记允许开展有界的实际验证，本身不能进入观测或地理位置投票。

三个候选不是三个节点副本。每个“精确目标＋方法＋必要视角”的共享 job 每轮最多三次实际执行机会，自有节点与 GP 合并计数；不能按节点、账户重新计算。机会耗尽不靠更换候选、分组或任务 ID 逃避限制；原 leased、已知远端 ID 和 unknown 继续覆盖其原需求，未知提交未解决时不重复发出或退款。新分组与历史结果、费用和回收身份的对应关系保留。

无论来自已有响应还是有限抽样，单 IP 回传都只说明该目标在实际方法和视角下的结果，不能提升为整个同质范围、BGP 父前缀的地区或 Anycast 结论。规则仍由每日固定的来源与适用观测融合生成，不新增自动地理投票或人工裁决流程。

后台仅根据最新 build 的清单有界差分：新增、实质变化或确需复测才更新。持久阶段/游标及 build fence 支持半同步恢复，旧清单不得覆盖最新需求。来源不变、证据仍有效时不全量重算，不运行旧每秒全量展开或旧域名同步路径。

一次规划轮次复用一条连接完成准备、重排和发现，缓存最多 32 条预编译语句；重排按最多 32 项的短事务分别提交，每批复核当前行和持久标记，不把连接生命周期变成事务生命周期。

差分未排空时暂缓旧来源需求的目标查找与规划，标记保留；同步完成后按实际最新状态消费一次。已有任务的领取/回执、DNS 到期和直接临时探测继续执行。这是同一后台循环的处理顺序，避免先规划将被退休的旧对象，并非暂停执行队列。

## 一个协调者持续补位

候选准备在事务外；事务内重新检查需求、指纹/版本、状态、能力、IPv4/IPv6、必要地区/ASN、容量及已有租约/远端意图，原子领取后异步下发。所有网络在事务外，QUIC 长连接复用，完成、能力变化和到期事件唤醒补位。

按可执行时间和稳定 ID 排序，有界扫描并持续翻页。能力过滤后领取，不能被不可执行队头阻塞。重试进入队尾，不增加复杂优先级层。

自有节点默认并发 10，每节点可调 1–1000，并遵守工作端实际容量；没有自有总并发上限。GP 优先领取自有节点覆盖不了的必要视角；没有可执行的此类工作时，再领取双方都可执行的共享任务。撤销“合格自有节点在线就禁止 GP”的旧排他规则，共享 pending 不等于自有节点已经占用。

预占绑定 attempt/token，心跳还校验当前在线 session；乱序心跳不能缩短截止时间、旧 session 不能延长新租约，旧容量通知不能重复填同一空位。断线只归还可证明未发送的预占；已开始的尝试保留原租约至回执到达或到期，供 spool 补传，重连继续使用受控容量；迟到结果不能完成新尝试。停用、重置和重启同样不能立即并发重派已经开始的尝试。

补位最多保留一个在途领取操作，等待数据库时继续处理控制帧和心跳；真正发送前重新检查当前会话与节点容量。一个心跳内的在线状态、能力及有效租约续期共用一次连接和短事务。回执原子落入既有 spool 后，上传或 ACK 超时只重传同一份回执，不重新执行测量，也不终止其他任务；真实连接中断仍由现有重连路径恢复。重传保留原观察时间和 attempt/token，25 秒 ACK 和 35 秒应用心跳期限不加长。

预占和发送准入属于同一个在途 worker。每个会话分别持有领取、心跳、回执连接，各缓存最多 64 条预编译语句；回执互斥仅覆盖该会话的数据库段，锁和事务不跨网络 ACK。认证、节点并发和运行 meta 的短查询复用物理只读连接，每次仍读取当前值，不缓存凭据、启停或容量，调用结束即释放读取快照。内嵌 SQLite 关闭项目未使用的全局内存分配统计，线程安全及 systemd 内存限制保持启用。

`UnsentDispatch` 在计次前持有原租约，尚未调用 Task send 时，迟到 worker 或丢弃结果会按持久原 session、token、attempt、轮次退还该次机会；不能影响替换会话的新尝试、已完成记录或 GP 意图。调用 send 前即解除 guard 的退款资格，此后的部分写入、超时和 ACK 丢失都不能当作未执行。

清单同步未完成也不放行旧需求：领取和发送准入核最新 manifest 的精确目标、方法与必要视角。有效在途及远端回收保留原身份，不按新来源指纹重发。通知只对已提交的可执行容量、能力、候选或持久重排变化发送；重复回执、ACK 和能力不变的心跳不重复广播，通知丢失仍有持久标记及既有定时检查恢复。

## 每轮最多三次实际执行

`attempt_seq` 是领取身份，每次领取单调增加并生成新 token；实际执行轮次/计数与可清零的失败链分开。每个共享 job 每轮最多三次实际执行是硬业务规则，自有节点与 GP 共用预算。有效证据已足够时停止后续工作。

- 执行器故障换另一个合适节点，必要时交 GP。
- 目标超时或拒绝同样保存本次观测，确实需要再确认时换观察者，优先不同运营商。
- 能证明没有实际执行的领取不消耗执行次数，但坏节点应退避，不能无限领取后拒绝。
- 耗尽冷却 24 小时是当前建议并实现的默认策略值。时间到不自动无限重开，必须由后续新鲜每日构建确认仍缺同份证据，才开启新轮；不把它包装成新的硬业务要求或证据有效性的保证。

正常到期后的新轮不累加过去的成功/失败次数；单调尝试身份、原回执和账目仍保留。DNS 沿用真实 TTL；非 DNS 不因为固定墙钟周期自动无限重探。未解决 GP unknown 跨轮、刷新或换 canonical ID 仍然防重。

用于寻找争议目标的 `discovery` DNS 与普通 DNS 需求分开处理：TTL 过期只让观测和候选失效，不自动把已完成的发现工作重新放到队头。仍有缺目标争议时，既有域名目录游标继续向后选择主机；只有目录再次选中一个已到检查时间的旧主机，才允许按原防重、冷却和在途检查重开同一个逻辑 job。普通 DNS 的 TTL 续测保持原语义；同一个 job 同时服务有效的人工 DNS 需求时，也按该人工需求续测，不取决于最初的 purpose。不人为抬高 TTL。升级前已经进入 pending/leased 的旧轮自然完成，不清理或改写历史执行和费用。

## 资格、回执和复用

回传核 job、attempt、token、执行方和指纹/版本，结果 ID 幂等。旧尝试只留可信历史，不能完成新尝试或覆盖后来的状态；费用和已知远端回收不因问题失去时效而消失。

实际方法/协议、精确目标、地区、必要 ASN 和响应都需验证。HTTP 成功、`finished`、请求地区或虚拟节点地区不是合格证据。目标无响应的正确路径是一次观测，不能变成目标位置答案，也不能仅因无法定位无限重试。

有效期从可信观察时间计算，重传和缓存命中不续期。DNS 使用答案与有限 CNAME 链的最短 TTL；候选 DNS 地址不升级为端点响应。ping/traceroute/BGP/登记国不自动变成位置事实，单 IP 结果不扩展到父前缀。失败、过期、无结论或矛盾观测不强盖来源。

trace 正响应默认 86400 秒、目标负响应默认 300 秒，是建议的新鲜度策略；领取 profile 可分别通过 `evidence_ttl_seconds`、`negative_evidence_ttl_seconds` 明确覆盖。旧合格收据没有保存绝对有效期时，正证据使用原观察时间加七天的兼容回退（当前 capture 同时有七天读取窗口），负响应使用短期限。七天不是重新接纳/重传后的续期，也没有新增前端配置项；这些默认值均不把 trace 到期变成自主周期重测。

所有对象都匹配合格观测，包括第三方来源一致者。可以直接回答事实且范围适用的近期合格观测优先；否则由独立有效来源映射大区后的严格多数、再按 IPLocate/DB-IP 主备顺序生成完整结果。解决分歧后不生成新任务。旧 accepted/ok 不能替代新资格检查，缺字段只留历史。

目前收据采集器实际只产生 DNS、可达性和目标负响应观测，没有可信目标位置/服务所有权事实生产入口。快照中这两类事实计数如实为零，不将探针地区、任意 target_country 字段、路径或 DNS 地址伪装为这种事实。

DNS 收据逐条保留实际 `query_name`、`query_type` 与 rcode；资格、发现候选及缓存/TLS 地址使用同一成功响应视图，不能用一条成功查询授权另一条失败的同类型 CNAME 查询。NXDOMAIN 可作为终结的 DNS 观察保存，但不从其别名生成正证据、地址 TTL 或缓存；仅有 SERVFAIL/REFUSED 时按执行器失败处理，混合响应只复用成功查询的记录。旧收据只有在上下文无歧义时复用，原始记录不改写。

构建快照中的 DNS 候选只解除精确范围的缺目标状态，仍须保留原时钟并在同步/发送时复核；缺失的可选发现导入不能使已冻结的有效候选丢失。有限 IPv4 抽样的选择依据没有观察时钟；真实结果的观察时间保存在执行记录中，不因选择来源标记保持不变就否认已有响应。自动 `endpoint-reachability` 只回答端点可达性，`repeat_on_build=false` 禁止因地理分歧持续存在、来源更新或该检查到期重开同一 trace；它不改变位置/Anycast 回退，也不取消其他明确需求的正常复测。

## Globalping 余额与发送

每账户独立查询 `/v1/limits` 免费余额/reset，扣除未确认预留后准入；没有本地小时或每日限额，不提供前端手填预算，也不以耗尽额度为目标。UTC 自然小时桶仅保存用量和审计，不是 provider 窗口或准入上限。

成本按探针测试数而非 HTTP 次数。实际提交启动至少间隔 5 秒，保留按免费余额/reset 延长节奏；同账户发送启动串行，响应异步。跨账户全局最多 16 个活动 GP 领取槽，轮询每轮 LIMIT 16 是另一限制。

领取事务条件插入 `gp_remote` 并绑定 job、attempt、原 token、账户、成本和窗口；不能用 `INSERT OR REPLACE` 覆盖旧意图。发送前再核官方余额、窗口、需求、容量和启动间隔。

GP 202 创建响应优先使用合法 body ID；没有合法 body ID 时，只从唯一、合法且同源的 `Location` 恢复配置 API 下的 measurement ID，不跟随任意返回 URL。后续仍向配置来源按 ID 回收。跨源、路径逃逸、身份信息、查询/片段或其他不合规头不能证明 ID，继续保留原不确定意图，不盲重发或退款。

| 状态 | 已知事实 | 恢复 |
|---|---|---|
| `prepared` | 可以证明未进入发送边界 | 重新准入，可幂等迁移未发送预留或撤销 |
| `sending` | 已持久进入发送边界 | 崩溃/超时/202 未保存 ID 均为不确定，不自动退款重发 |
| `submitted` | remote ID 已持久保存 | 按 ID 独立回收，不因需求关闭停止 |
| `unknown` | 可能已发送但没有可靠 ID | 保留账目和需求防重，先恢复核账，不换 ID 绕过 |

可证明未发送的预留跨 UTC 归档桶先幂等转账并重核 provider 准入，不能先发后补账；换桶不增加余额。释放活动槽不等于退款，换小时不抹旧账。明确未创建的拒绝才可退款。

正常轮询排除空 ID，按到期时间处理，异常账户退避，unknown 不能占满已知 ID 回收批次。账号修改、停用或删除保留必要快照/凭据引用，凭据失效后保留恢复记录。终结远端状态须匹配原 attempt/token，不能误删后来记录。

资源页“最近探测”是 measurement ID 去重后的滚动最近 3600 秒实际测试数，与 UTC 审计桶、保守预留和完成任务数分开。其他客户端同时使用账户时，provider GET/POST 不是原子扣账，不能承诺外部恰好执行一次或绝对零积分消耗；报告 credits 消耗时暂停当前窗口新提交。

## 旧库切换和回退

先用 SQLite backup API 或 `.backup` 取得一致副本，在独立 root/data、fixture 凭据及隔离出站环境演练。不能仅复制活跃 WAL 主文件，也不能把 `--offline` 当成全系统断网。规则 release、内部 build、缓存和凭据引用需共同盘点。

迁移保留旧 ID/token/attempt 命名空间、结果、旧决定、目标来源、费用、租约、已知 ID 和 unknown。旧物理副本映射到同一逻辑需求；新领取覆盖该需求全部旧 leased 和未决远端状态，不能换任务 ID 再提交。旧结果按新资格复核，不能仅凭 accepted/ok 或虚拟地区复用。历史决定保留只读，不参与每日自动选择。

生产切换需要单独批准。停止旧控制器和旧生成入口后只启一个新路径，不长期双写/双规划；核对最新清单同步、export pending、旧在途及费用后才允许真实领取/发布。

没有 `migrate --dry-run` 或全局“只暂停新领取”的 CLI。`serve --interval-hours 0` 只关闭周期构建；`--offline` 只影响构建来源缓存。回退先停止控制器，核旧版本是否识别新任务/尝试/账目；不能用旧备份覆盖切换后的结果、费用和远端状态。优先向前修正兼容性，不无条件热降级。
