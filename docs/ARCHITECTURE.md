# 每日构建与共享补证

本文件说明当前规则生成与观测链路的实现合同。验证入口、性能测量方法和证据边界见 [VALIDATION.md](VALIDATION.md)，具体部署资料由部署方在仓库外维护。

## 两条配合的流程

```text
每日构建：固定来源 + 固定已有观测 + 判断规则
       → 规范化、范围对齐、确定性选择、等价压缩、验证
       → 完整规则集 + IP 库 + 私有待补证清单
       → O(1) 激活必要版本指针

后台补证：最新清单有界差分 → 共享 jobs
       → 自有节点 / Globalping 异步执行
       → 保存原始观察时间和合格证据
       → 下一次每日构建使用
```

构建不等待新测量，回执不逐条触发重建。范围是生成通用规则和 IP 数据，不引入人工裁决平台，不设计客户端出口动作。`/api/decision` 不再提供写入入口；旧 `decisions` 和相关历史保留，但不作为新构建输入。

保留 SQLite WAL、单进程控制器、共享任务队列、必要租约/远端恢复状态、已证明有读取收益的投影及普通 Git 发布。不引入新的数据库服务、消息平台或 controller outbox。

## 输入与确定性选择

`config/recipes.json`、来源配置、服务边界和判断策略是权威输入。Git 来源先固定 SHA，其他来源固定内容哈希；配置及已有观测在本轮捕获后冻结，解析、计算和文件准备不持有在线写事务。相同来源、配置与观测快照必须得到相同产物。下载时间、文件更新时间和无关来源变化不使全部观测失效。

压缩地理来源按流解析，仍检查展开上限、地址族和完整性，不同时保留完整展开文本。规则与 IP 库逐段进入同一个增量哈希，保持原有字节边界和版本身份。私有争议逐项写入未激活的 manifest，完整 payload 不再另存一份大列表；压缩前接受的 exact/suffix 域名直接借用写入同一私有事务，保留全部主机名和 bucket 最小值，不另建克隆列表。来源、观测和解析缓存用完即释放。GEO 集合只在当前验证成功且没有后续配方消费者时释放，Anycast 保留到全局使用结束，不能为了降峰提前丢失范围或验证依据。

地理等价校验直接借用两侧规则，沿用精确类型、修饰符、地址族的数值区间并集比较；不为验证重新 clone、优化并生成两份完整 CIDR 规则集。地址洞与源/目的方向仍参与相等判断，CN 允许的域名谓词单独按既有合同处理。

每个对象均匹配适用的已有观测，包括第三方来源一致的对象。IP 范围依次采用：

1. 能直接回答该事实、范围确实适用、近期合格且互不矛盾的观测。
2. 同类地理来源先归一化并映射为大区，独立有效来源形成严格多数时采用多数。
3. 无严格多数时采用明确主备顺序：IPLocate 为主，DB-IP 为备。

镜像和同源接口不重复计票，缺失不投反对票。失败、过期、无结论或互相矛盾的观测不强盖来源。ping、traceroute、BGP 起源或登记国不是目标物理位置，单 IP 证据不能扩大为整个前缀。有效分歧按上述确定性策略输出，并把仍缺证据的问题留在私有清单，不能直接剔除有效范围。全部来源及适用观测均无信息时明确报告覆盖缺口，按覆盖契约处理，不伪造或静默遗漏。

当前实际接入的 DNS/traceroute 收据只能证明 DNS 回答、可达性及目标负响应，没有能够独立产生目标位置或服务所有权事实的可信导入源。`fusion::capture` 因此如实报告 `qualified_target_location_facts=0`、`qualified_domain_owner_facts=0`。位置/所有权优先分支不能被描述成已从路径推导出地理真值；当前归属仍按可用来源策略选择，路径与 DNS 证据只在其确实能回答的范围内复用。

冻结快照会从合格收据提取精确公网 DNS 候选和端点响应，保留原观察时间、来源与 TTL，每 IP 只保留一份紧凑依据。生成可测事项时只在其精确范围内取最多三个目标，写入既有 `targets`/`target_evidence`；旧目标为空时可由清单恢复有效候选，不覆盖非空人工或在途选择。`endpoint-reachability` 只检查端点可达性，标记 `repeat_on_build=false`，不能因同一位置分歧、来源更新或该证据到期反复重开；位置及 Anycast 仍按原范围和来源策略表达，不能宣称已被 trace 解决。

域名按对应服务分类、明确官方端点、有效来源和配方边界生成。CNAME、DNS 地址、CDN 或 IP 地区不能反推服务身份。exact/suffix/keyword/wildcard/regex、进程、端口和 ASN 等条件保留可忠实表达的原子语义；格式损坏、非法谓词或不能等价转换的规则仍使验证失败，不把 AND/NOT 拆成 OR。

PSL、共享基础设施边界、配方排除和明确服务用途用于规范化规则范围。多集合正常嵌套不制造虚假冲突。原子谓词保留到最终导出，覆盖去重必须有最终保留谓词的证明；CIDR 比较方向、地址族和全部修饰符的精确区间并集，保留地址洞。域名发现目录取压缩前完整接受的行，不从压缩后的 `.list` 反推。

中国大陆唯一公开集合为 `region/cn`，域名优先、IP 兜底，`cn-geo` 仅是内部地区 ID。运营商网络分类、BGP、公共 geofeed 是不同语义的辅助线索，不能混入物理位置票。范围明确的 Anycast 独立表达，疑似多地证据不能扩张为父前缀；最终地区及 Anycast 范围验证保持准确。

## 公开产物与内部快照

公开不可变目录为 `data/releases/<release_hash>/`，包含四类规则目录、`README.md` 和正式 IP 库 `ip-library.csv`。CSV 列为 `family,start,end,region,anycast`；family 为 4/6，起止为包含端点的精确范围，region 与 `region/*` 规则集使用同一公开标识（如 `cn`、`us`），内部 `cn-geo` 通过现有配方绑定映射成 `cn`，anycast 为 true/false。CSV 参与版本哈希、完整文件校验、下载和 Git 发布，不附带原始证据。

内部目录按 `build_id` 关联，位于 `data/internal-builds/<build_id>/`。公开规则相同不代表内部补证事项相同；不能用公开 hash 代替 build ID。新目录只保留 `manifest.sqlite3` 与 `build.json`：原始争议完整 payload 在 manifest 的 cases 表，domains 表取自压缩前完整接受规则中的可发现 exact/suffix 主机名，ranges 只索引可执行观测需要的范围。取消重复写出的 conflicts/domains JSONL，旧历史文件不删除。详细来源/观察依据不进入公开目录。

计算、排序、差分准备和文件验证在写事务外完成。激活只提交当前 build/release、必要构建终态、持久同步/导出标记，不在激活事务全量写 cases/jobs 或派生数据。真实激活耗时及写量应实测，不以更名或后台搬运代替性能证据。

## 最新清单的有界同步

独立后台按最新已激活 build 的私有清单分页比较待测数据，只新增、实质变化或确需复测时写入，不变项不改 `updated`、不复制任务。每个短批次复核当前 build fence、新证据、目标、租约和未决远端意图。半同步中断可恢复；旧 build 的迟到批次不能重新激活已消失的需求或覆盖最新清单。

一次规划轮次用同一条连接完成准备、重排和目标发现，预编译语句缓存有界，重排每批最多 32 项并分别提交。连接复用不延长事务或读取快照。清单同步期间，领取和实际发送还会读取最新 manifest，拒绝已经退出或目标、方法、必要视角已改变的旧需求；这个发送准入检查不抹去有效在途、已知远端 ID、费用或旧回执的原尝试身份。

`build-sync-pending` 保存 build、阶段、游标和统计，完成后有持久完成记录。它是恢复游标，不是另一套执行队列。域名索引同样按接受清单差异更新；`facts` 留作历史，旧全量域名同步和旧任务展开入口停用。不能为减表数删除仍有作用的需求列表/计数投影，也不能同时运行两套规划器。

清单差分未完成时，后台先完成这些短批同步，再准备来源需求和目标发现，避免对即将退休的旧对象先规划一次、退休后又重排一次。其间已有队列的领取、实际发送、回执和 DNS 到期处理继续运行；人工临时探测及已知目标登记仍直接生成对应工作。无需增加第二队列或另一种状态。

构建不覆盖人工临时探测目标、租约、回执、费用和 GP 状态。新结果留给下次构建，后台同步也须在实际领取前检查证据是否已经足够。没有确切可测目标时保留等待，不生成假 traceroute，不扫描前缀填队列。

## 观测与调度

同一目标、方法和必要视角表达同一份缺失证据，不按节点、账户或 build 复制。一个协调者按能力、容量和可执行时间原子领取，网络在事务外异步发送/回收，QUIC 连接复用。预占、心跳、断连、重连和迟到回执绑定原 attempt/token，旧空位通知不能造成重复派发。可证明未发送的自有预占在断连/停用等情况下立即归还；已实际开始的尝试保留原 token/租约到有效补传或截止时间，不能立刻并发重派同一工作。

每个工作会话分别持有领取、心跳和回执连接，各自最多缓存 64 条预编译语句；预占与发送准入共用一个在途 blocking worker，等待写锁时继续处理控制帧。回执只串行化该会话的数据库段，互斥锁和 SQL 事务都不跨 ACK 网络发送。`UnsentDispatch` 保留尚未调用 Task send 的证明，即使 worker 迟到或结果被丢弃，也只按持久原 session、token、attempt 和轮次幂等退还那次机会；调用 send 前即解除退款资格，部分发送、ACK 丢失和 GP unknown 继续保守恢复。

通知只提示重新检查：实际队列、能力或候选变化在提交后通知，重复回执、ACK 和未改变能力的普通心跳不额外广播。需要恢复的重排仍有持久标记，不能依靠一次内存通知维持正确性。DNS 资格、候选提取和缓存/TLS 地址共用按实际查询名、类型及 rcode 筛选的成功响应视图；保留原始回执，不把失败的辅助查询或 CNAME 后续查询混成正证据。

GP 优先自有节点覆盖不了的必要视角；没有这类可执行工作时，也领取双方都能执行的共享任务。自有节点在线不再排他阻止 GP。每节点默认并发 10，可调 1–1000，无自有全局上限。GP provider-only 免费余额/reset、实际至少 5 秒启动间隔、既有按余额延长节奏和全局 16 活动槽保持。

每需求每轮最多三次实际执行是硬业务上限，自有/GP 合并计数，证据足够立即停止。执行器故障换合适执行方，目标超时/拒绝也保存这次观测，确需确认时优先换运营商。确定未执行不计实际次数，但不能让坏节点反复领拒。耗尽冷却 24 小时是当前建议并实现的默认策略值，仅在新的每日构建仍需同份证据时开启新轮；不是每过 24 小时无条件重测，也不是证据正确性的保证。

详细额度、尝试及兼容合同见 [SCHEDULING.md](SCHEDULING.md)。观测有效期按原始可信时间，重传不续期；DNS 沿用 TTL。trace 正响应 86400 秒、目标负响应 300 秒是建议的新鲜度默认，可由明确 profile 策略覆盖；旧无期限合格证据使用七天兼容回退。它们不是固定周期重测规则。公共 Atlas 仅读取既有测量，不新建 Atlas 测量。DNS 候选、端点响应和位置事实不能互相冒充。

## 导出、Git 与界面

SQLite 当前 build/release 是下载权威。`dist` 是便捷导出；持久 `export-pending`、版本复核和共用 guard 防止旧导出覆盖新版本，确认失败后只恢复当前版本。不能因文件已切换而误称旧目录仍在。

Git 队列持久绑定 build/release、仓库、分支、基线和 prepared commit SHA。未发送旧目标合并，重试不 fetch/rebase 旧产物为新提交。发送前核最新目标，普通非 force push 后 `ls-remote` 核 SHA；超时先核原 SHA/祖先关系，不能证明则保留 unknown，不盲推。旧无持久 SHA 的不确定发送保留待核账。API 区分本地当前与远端已核实版本。

控制台“规则核查”合并原来的争议与任务入口，只有三个计数单位：规则问题、去重任务、原尝试的执行记录。问题读取指定 build 的完整私有 manifest，在线 cases 仅用于同指纹的补充材料进度，不为展示不可测分歧重写在线队列。任务直接按共享 jobs ID 列出，一份任务可服务多个问题；执行记录按原尝试身份追溯，重复回执不算新执行，无法复原身份的旧资料保留为历史。历史构建、结果、费用及远端恢复记录不删除。

“本轮规则采用什么依据”与“补充材料进度”分别显示：任务回传、证据资格、证据是否新鲜、是否能回答当前事实均不是同一状态。无目标的问题不计为待执行任务，DNS 候选不冒充已响应 IP，traceroute 不冒充地区或 Anycast 真值。业务探测和仅辅助目标发现互斥归类：当前同时服务业务与辅助发现的任务归业务，详情保留多用途，所有用途仍按 job ID 去重。Globalping 探针测试数与任务/执行记录数分开，未知提交继续保留意图与费用。

三个视图的列表与统计使用相同筛选，独立异步加载；关联跳转保留问题/任务筛选，旧 `#conflicts`、`#tasks` 地址兼容进入合并页面。临时探测和补充精确目标继续使用原入口，没有人工归属决定表单。新界面只读既有数据，读取索引不改变调度或回执写入。构建页分别展示规则完成和后台同步状态，不把未即时计算的差异显示成零。规则目录提供 `/api/ip-library` 的正式下载入口。

前端仍为内嵌 React/TS/Vite/Mantine/TanStack，无新框架或运行服务。列表、统计及发现状态独立异步读取，详情按需加载，SQLite 阻塞操作不占 HTTP/QUIC 网络执行器。性能与生产状态只以实际证据为准。

## 控制台会话

控制台使用固定 HS256 算法和固定 issuer/audience 的 JWT，沿用 8 小时会话期限与 HttpOnly、SameSite=Strict Cookie；HTTPS 登录增加 Secure。数据目录内独立随机的 32 字节主密钥通过带域隔离的 HMAC 绑定当前管理员凭据摘要，重启复用，更换管理员凭据使旧会话失效。管理员 Bearer 与节点认证路径保持独立。

普通请求只验证签名、声明、有效期和内存撤销摘要，不访问 SQLite 或文件。退出将当前 jti 的摘要和到期时间写入 0600 撤销文件，文件和目录同步完成才返回成功；失败可幂等重试，跨域修改检查仍有效。启动时恢复撤销列表，坏格式或不安全权限拒绝启动，不能静默更换密钥。两个文件为 `console-session-key` 与 `console-session-revocations.json`，随数据目录保留，不能公开或用旧备份覆盖。首次升级不能迁移只在旧进程内存里的不透明会话，需要重新登录；回退到旧认证二进制同样需登录，不回滚业务数据库。
